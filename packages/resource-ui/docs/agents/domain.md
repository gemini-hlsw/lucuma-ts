# Domain docs

- Glossary: `packages/resource-ui/docs/GLOSSARY.md`
- ADRs: `packages/resource-ui/docs/adr/`

## Reading them

Before exploring an area, read the glossary and any ADR that touches it. Name domain concepts with the glossary's terms in titles, tests, and proposals. When your output contradicts an ADR, say so and name the ADR.

A missing glossary or ADR folder is normal: carry on without mentioning it. `domain-modeling` creates them at these paths the first time a term or decision is settled.
